# 복원, Command, UI 정책 (Restoration & UI Policy)

## 1. 복원은 비즈니스 진실을 복원하는 것입니다

화면 전환 인자(Navigation Arguments)와 저장된 데이터로부터 가장 안전하게 확인된 비즈니스 상태를 재구성하세요. 프로세스가 재생성되었다는 이유만으로 부작용이 있는 위험한 작업을 자동으로 재실행하지 마세요.

비동기 작업이 진행 중이던 상태를 복원하기 전에 복구 규칙을 제품 관점에서 먼저 정의해야 합니다. 서버나 Repository가 이전 작업의 완료 여부를 증명할 수 없다면, 작업이 안전하게 계속 실행 중인 것처럼 가장하지 말고 편집 가능 상태나 명시적인 상태 불확실(`StatusUnknown`) 상태로 복원하세요.

---

## 2. Command는 실행 요청입니다

머신은 순수 값(Value)으로 Command를 발행하고, Android 호스트(ViewModel)가 이를 실행합니다. Command의 결과는 다시 Event로 머신에 전달됩니다. 상태 수집(State observation) 자체가 Repository 작업을 트리거해서는 안 됩니다.

순차 Command는 발행된 순서를 엄격히 보존하며, Phase 소유의 `invoke` 비동기 작업은 해당 Phase를 벗어날 때 자동으로 취소됩니다.

---

## 3. UI 동작의 경계

1. 제품의 비즈니스 진행 상태는 항상 **State**에 표현합니다.
2. UI에서 시작된 순수 UI 인터랙션은 **직접 UI 콜백**을 사용합니다.
3. 비동기 비즈니스 결과로 인해 화면 이동이 필요하다면 Route 컴포저블에서 지속되는 **완료 State**를 관찰합니다.
4. 반복 처리가 위험한 경우 State에 명시적으로 확인(Acknowledged) 상태를 모델링합니다.

---

## 4. SavedStateHandle 소유권

`SavedStateHandle`의 소유권은 `ViewModel`에 있습니다. 순수 Kotlin 머신은 복원된 상태 값을 전달받을 뿐 Android 의존성을 갖지 않습니다. 비즈니스 진행 상태를 재구성하는 데 꼭 필요한 식별자(ID 등)만 저장하세요.

초기 상태 구성 시에는 `onEnter`가 실행되지 않습니다. 복원된 상태는 이미 확인된 진실을 나타내야 하며, 새로운 작업을 시작하라는 암시적 요청이 되어서는 안 됩니다.
